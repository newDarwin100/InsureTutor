# SSE 首字响应验收

TTFT 从 HTTP 提交问题到客户端收到第一个非空答案文字计算；加载提示、SSE 心跳及模型输出中的 JSON 字段不计入。全部使用真实 OpenAI 调用，问题是之前已授权的 D01、D05、D06。D06 在同一测试会话中紧接 D05。

| 题目 | 首轮 TTFT | 优化后 TTFT | 优化后生成 | 优化后核对 | 优化后完整耗时 |
| --- | ---: | ---: | ---: | ---: | ---: |
| D01：4%保证 + 定期提款 | 3.21s | 1.99s | 4.51s | 1.80s | 7.09s |
| D05：定期提款条件 | 1.60s | 1.75s | 3.25s | 2.60s | 6.30s |
| D06：那每年提款呢？ | 3.61s | 1.57s | 2.58s | 1.53s | 4.57s |

两轮均返回 answered，临时流式段落与最终段落一致。JSON 保留全部答案、原文引用、各阶段耗时、用量和第一轮结果，不覆盖失败目标记录。最新版均未命中查询向量缓存，不能把结果归功于缓存。

首轮 D01 的问题向量化耗时1.70s，已经用掉大部分首字预算；D06 的模型追问改写耗时1.64s。随后对上一问题对象明确的每月/每年提款追问使用本地补全，改写耗时降到约0.001s；仍重新检索原文，不从旧答案复制保险事实。其余阶段也有 API 波动，第二轮提款题的核对反而更慢，不能把所有差异都算作代码优化收益。

人工抽查确认三题核心利率/提款条件与引用相符；D01 此次没有在正文明确写出2022年1月，而引用脚注包含该日期。这项表述完整性仍需后续答案回归，模型核对通过不等于所有预期检查均通过。

2秒目前只是目标。三个样本不足以证明稳定p95，更不能保证首次请求、歧义追问和所有问题都小于2秒。SSE改善先看到内容的时间，不会消除生成和最终核对的完整耗时。
